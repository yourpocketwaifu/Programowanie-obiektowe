Klasy i pola 📦
Klasa to szablon — obiekt to konkretny egzemplarz

Klasa opisuje co obiekt posiada (pola) i co potrafi (metody). Obiekt to instancja klasy — tworzysz go przez new.

Java — podstawowa klasa 
public class Point {
    // pola prywatne — nie widoczne z zewnątrz klasy
    private double x;
    private double y;

    // pole finalne — wartość ustalona raz na zawsze
    public final String label = "punkt";

    // pole statyczne — jedno dla WSZYSTKICH obiektów klasy
    private static int count = 0;

    // metoda statyczna — wywołujesz przez Point.getCount(), nie przez obiekt
    public static int getCount() { return count; }
}
🔒 Kiedy private?
Prawie zawsze. Pola chronisz przez gettery/settery — to hermetyzacja.
📌 Kiedy static?
Gdy dane dotyczą całej klasy, nie jednego obiektu (np. licznik instancji, stała PI).
🔑 Kiedy final?
Gdy wartość nie powinna się zmieniać po ustawieniu — stałe, wartości konfiguracyjne.
🆕 Tworzenie obiektu
Point p = new Point(1.0, 2.0); — new wywołuje konstruktor i zwraca referencję.

Konstruktory 🏗️
Specjalna metoda wywoływana przy tworzeniu obiektu

Konstruktor ma tę samą nazwę co klasa i nie ma typu zwracanego. Może być kilka konstruktorów (różne parametry).

Java — rodzaje konstruktorów 
public class Point {
    private double x, y;

    // 1. Bezargumentowy — wartości domyślne
    public Point() {
        this.x = 0;
        this.y = 0;
    }

    // 2. Z parametrami — ustawia wartości
    public Point(double x, double y) {
        this.x = x;   // this.x = pole, x = parametr
        this.y = y;
    }

    // 3. Kopiujący — tworzy niezależną kopię innego obiektu
    public Point(Point other) {
        this.x = other.x;
        this.y = other.y;
    }

    // 4. Łańcuchowanie — this() woła inny konstruktor tej samej klasy
    public Point(double x) {
        this(x, 0);   // musi być PIERWSZA linia
    }
}
⚠️
Konstruktor kopiujący to głęboka kopia — tworzy nowe obiekty, nie kopie referencji. Bez niego ktoś może modyfikować twój obiekt z zewnątrz przez referencję!
Java — głęboka vs płytka kopia tablicy 
// PŁYTKA kopia — tablica nowa, ale obiekty w środku te same!
this.points = Arrays.copyOf(other.points, other.points.length);

// GŁĘBOKA kopia — każdy punkt to zupełnie nowy, niezależny obiekt
this.points = new Point[other.points.length];
for (int i = 0; i < other.points.length; i++) {
    this.points[i] = new Point(other.points[i]); // konstruktor kopiujący
}

// super() — wywołanie konstruktora klasy nadrzędnej (musi być PIERWSZA linia)
public Polygon(Point[] points, Style style) {
    super(style);   // wołamy konstruktor Shape(style)
    this.points = ...;
}

Akcesory i mutatory (gettery/settery) 🔁
Kontrolowany dostęp do prywatnych pól
Java — gettery i settery 
public class Person {
    private String name;
    private int age;

    // Akcesor (getter) — zwraca wartość pola
    public String getName() { return this.name; }
    public int    getAge()  { return this.age; }

    // Mutator (setter) — ustawia wartość pola (z opcjonalną walidacją)
    public void setName(String name) {
        if (name == null || name.isBlank())
            throw new IllegalArgumentException("Imię nie może być puste");
        this.name = name;
    }

    // Getter obiektu mutowalnego — zwróć KOPIĘ, nie oryginał!
    private Point position;
    public Point getPosition() {
        return new Point(this.position);  // kopia — nie oryginał
    }
}
💡
Klasa niemutowalna (immutable) — tylko gettery, żadnych setterów. Po utworzeniu obiektu nikt nie może zmienić jego stanu. Przykład: String, LocalDate, wszystkie rekordy.

Dziedziczenie 🧬
Klasa potomna przejmuje cechy rodzica

Słowo kluczowe extends — klasa dziedziczy pola i metody z klasy nadrzędnej. Java pozwala dziedziczyć tylko po jednej klasie (ale implementować wiele interfejsów).

Java — hierarchia klas Shape → Polygon → SolidFilledPolygon 
public abstract class Shape {
    protected Style style;   // protected — widoczne w podklasach

    public Shape(Style style) { this.style = style; }

    public abstract String toSvg();  // musi być zaimplementowana
}

public class Polygon extends Shape {
    private Point[] points;

    public Polygon(Point[] points, Style style) {
        super(style);          // ← MUSI być pierwszą linią
        this.points = points;
    }

    @Override
    public String toSvg() { return "<polygon .../>"; }
}

public class SolidFilledPolygon extends Polygon {
    private String color;

    @Override
    public String toSvg() {
        return super.toSvg() + " fill=\"" + color + "\"";
        // super.toSvg() — wywołuje metodę rodzica
    }
}
super() — konstruktor
Wywołuje konstruktor klasy nadrzędnej. Musi być pierwszą linią konstruktora.
@Override
Informuje kompilator, że nadpisujesz metodę rodzica. Nie obowiązkowe, ale jeśli popełnisz literówkę — kompilator wyłapie błąd.

Klasy abstrakcyjne 👻
Szablon którego nie możesz zinstancjonować bezpośrednio

Klasa abstrakcyjna może mieć metody abstrakcyjne (bez ciała) i zwykłe (z ciałem). Nie można jej użyć przez new Shape() — tylko przez podklasy.

Java — klasa abstrakcyjna 
public abstract class Shape {
    protected Style style;

    public Shape(Style style) { this.style = style; }

    // abstrakcyjna — brak ciała, podklasa MUSI ją zaimplementować
    public abstract String toSvg();

    // zwykła — ma ciało, podklasa MOŻE nadpisać
    public String describe() { return "Figura geometryczna"; }
}

// ❌ Błąd kompilacji!
Shape s = new Shape(style);   // nie można tworzyć instancji klasy abstrakcyjnej

// ✅ Poprawnie — przez podklasę
Shape s = new Polygon(points, style);

Interfejsy 📋
Kontrakt — klasa musi dostarczyć wszystkich metod
Java — interfejs i implementacja 
// Definicja interfejsu
public interface Shape {
    String toSvg(String params);  // metoda bez ciała — MUSI być zaimplementowana

    // metoda domyślna (default) — ma ciało, klasa może (nie musi) nadpisać
    default String toSvg() { return toSvg(""); }
}

// Klasa implementuje interfejs
public class Polygon implements Shape {
    @Override
    public String toSvg(String params) {
        return String.format("<polygon points=\"%s\" %s />", pointsStr, params);
    }
}

// Klasa może implementować WIELE interfejsów
public class Person implements Comparable<Person>, Serializable { ... }

// Interfejs Comparable — sortowanie własnych obiektów
public class Person implements Comparable<Person> {
    @Override
    public int compareTo(Person other) {
        return this.birthday.compareTo(other.birthday);
        // ujemna = this jest "mniejszy", 0 = równe, dodatnia = this "większy"
    }
}

Polimorfizm 🎭
Jeden typ — różne zachowanie zależnie od obiektu
Java — polimorfizm i rzutowanie 
// Lista heterogeniczna — różne typy, wszystkie są Shape
List<Shape> shapes = new ArrayList<>();
shapes.add(new Polygon(...));
shapes.add(new Ellipse(...));
shapes.add(new Circle(...));

// Każdy wywołuje SWOJĄ wersję toSvg() — Java decyduje w runtime
for (Shape s : shapes) {
    System.out.println(s.toSvg());  // polimorficzne wywołanie
}

// instanceof — sprawdź rzeczywisty typ obiektu
if (s instanceof Polygon polygon) {   // Java 16+ pattern matching
    polygon.getPoints();              // dostęp do metod Polygon
}

// Stara składnia rzutowania
if (s instanceof Polygon) {
    Polygon polygon = (Polygon) s;   // explicit cast
}
✅
Polimorfizm działa bo Java w czasie działania (runtime) sprawdza rzeczywisty typ obiektu, nie typ zmiennej. Shape s = new Polygon(...) — zmienna jest typu Shape, obiekt jest Polygon. Przy wywołaniu s.toSvg() wywoła się Polygon.toSvg().

Comparable i Comparator 🔢
Jak sortować własne obiekty
Comparable — sortowanie naturalne
Klasa implementuje compareTo() — jeden domyślny porządek na zawsze. Sortuj: Collections.sort(list).
Comparator — sortowanie na żądanie
Osobna lambda/klasa porównująca dwa obiekty — wiele różnych porządków. Sortuj: list.sort(comparator).
Java — wzorce sortowania 
// naturalny porządek (wymaga implements Comparable)
list.sort(Comparator.naturalOrder());

// odwrócony
list.sort(Comparator.reverseOrder());

// po konkretnym polu
list.sort(Comparator.comparing(Person::getBirthday));

// malejąco po polu
list.sort(Comparator.comparing(Person::getBirthday).reversed());

// wielokryteryjne — najpierw po nazwisku, potem imieniu
list.sort(Comparator.comparing(Person::getSurname)
                   .thenComparing(Person::getName));

// lambda — od najstarszego
list.sort((a, b) -> a.getBirthday().compareTo(b.getBirthday()));

equals(), hashCode() i toString() 🪪
Trzy metody które każda klasa powinna mieć
Java — equals, hashCode, toString 
public class Point {
    private double x, y;

    // equals — porównanie zawartości (nie referencji)
    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;           // ta sama referencja
        if (!(obj instanceof Point other)) return false;
        return Double.compare(x, other.x) == 0
            && Double.compare(y, other.y) == 0;
    }

    // hashCode — ZAWSZE razem z equals! Ten sam equals → ten sam hashCode
    @Override
    public int hashCode() {
        return Objects.hash(x, y);
    }

    // toString — czytelna reprezentacja obiektu (używana przy println)
    @Override
    public String toString() {
        return String.format("Point(%.2f, %.2f)", x, y);
    }
}

// Użycie
Point p1 = new Point(1, 2);
Point p2 = new Point(1, 2);
p1 == p2;           // false — różne obiekty
p1.equals(p2);    // true — ta sama zawartość
System.out.println(p1);  // "Point(1.00, 2.00)" — wywołuje toString()
⚠️
Jeśli nadpisujesz equals(), musisz nadpisać też hashCode()! Inaczej obiekty "równe" przez equals() będą się różnić jako klucze w HashMap i HashSet.

Wzorzec Dekorator 🎀
Opakowuj obiekt i rozszerzaj jego zachowanie

Dekorator opakowuje obiekt i dodaje mu nowe funkcje bez zmiany oryginalnej klasy. Dekoratory można układać w stos.

Java — Dekorator 
// Bazowy dekorator — implementuje interfejs i trzyma dekorowany obiekt
public class ShapeDecorator implements Shape {
    protected Shape decoratedShape;

    public ShapeDecorator(Shape shape) {
        this.decoratedShape = shape;
    }

    @Override
    public String toSvg(String params) {
        return decoratedShape.toSvg(params);  // deleguj dalej
    }
}

// Konkretny dekorator — dodaje kolor wypełnienia
public class SolidFillDecorator extends ShapeDecorator {
    private String color;

    public SolidFillDecorator(Shape shape, String color) {
        super(shape);
        this.color = color;
    }

    @Override
    public String toSvg(String params) {
        return decoratedShape.toSvg(
            String.format("fill=\"%s\" %s", color, params));
    }
}

// Użycie — dekoratory układamy w stos
Shape polygon = new Polygon(...);
Shape filled  = new SolidFillDecorator(polygon, "red");
Shape stroked = new StrokeDecorator(filled, "black", 2.0);

        return this;   // ← kluczowe! zwraca siebie → łańcuchowanie
    }
    public PersonBuilder age(int age)    { this.age = age;     return this; }
    public PersonBuilder email(String e) { this.email = e;     return this; }

    public Person build() {
        return new Person(name, age, email);  // tworzy gotowy obiekt
    }
}

// Użycie — czytelne łańcuchowanie

    .name("Ada")
    .age(25)
    .email("ada@example.com")
    .build();

Wzorzec Observer (Obserwator) 👀
Automatyczne powiadamianie o zmianach stanu

Observer to wzorzec zdarzenie → reakcja. Obiekt (Subject) trzyma listę obserwatorów i powiadamia ich gdy coś się zmieni. Używany np. w GUI, evencie gry, systemach powiadomień.

Java — Observer z interfejsem funkcyjnym 
// Interfejs obserwatora — może być lambdą!
public interface GameObserver {
    void onEvent(String event);
}

// Subject — trzyma listę obserwatorów i notyfikuje
public class Game {
    private List<GameObserver> observers = new ArrayList<>();

    public void addObserver(GameObserver obs) { observers.add(obs); }
    public void removeObserver(GameObserver obs) { observers.remove(obs); }

    private void notify(String event) {
        for (GameObserver obs : observers) obs.onEvent(event);
    }

    public void playerScored(String player) {
        // ... logika ...
        notify("SCORE:" + player);  // powiadom wszystkich
    }
}

// Użycie — obserwator jako lambda
Game game = new Game();
game.addObserver(event -> System.out.println("[LOG] " + event));
game.addObserver(event -> gui.updateScoreboard(event));

// Wariant z Consumer (standardowy interfejs funkcyjny)
private List<Consumer<String>> listeners = new ArrayList<>();
public void addListener(Consumer<String> l) { listeners.add(l); }
private void fire(String msg) { listeners.forEach(l -> l.accept(msg)); }

Generyki — typy szablonowe 🔧
Jeden kod działający dla dowolnego typu
Java — klasa generyczna, metoda generyczna, ograniczenia 
// Klasa generyczna — T to placeholder na typ
public class Pair<A, B> {
    private A first;
    private B second;

    public Pair(A first, B second) { this.first = first; this.second = second; }
    public A getFirst()  { return first; }
    public B getSecond() { return second; }
}

// Metoda generyczna — T deklarujesz przed typem zwracanym
public static <T> List<T> filterByClass(List<?> list, Class<T> clazz) {
    List<T> result = new ArrayList<>();
    for (Object obj : list) {
        if (clazz.isInstance(obj)) result.add(clazz.cast(obj));
    }
    return result;
}

// Ograniczenie — T musi być podtypem Comparable
public static <T extends Comparable<T>> T max(List<T> list) {
    return list.stream().max(Comparator.naturalOrder()).orElseThrow();
}

// Wildcard — ? gdy nie wiesz jaki typ (tylko czytasz, nie piszesz)
public void printAll(List<?> list) {
    list.forEach(System.out::println);
}
