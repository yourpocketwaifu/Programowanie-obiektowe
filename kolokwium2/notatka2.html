Jak działa serwer TCP? 🌐
ServerSocket — serce każdego kolokwium

Wyobraź sobie serwer jak recepcjonistę w hotelu. Siedzi przy ladzie i czeka na gości. Gdy ktoś wchodzi, recepcjonista go rejestruje i oddaje mu klucz. W Javie to działa tak samo:

💡
ServerSocket = recepcjonista czekający na gości
Socket = połączenie z jednym konkretnym gościem
accept() = moment kiedy gość wchodzi — metoda blokuje się do tego czasu

Minimalna klasa Server

Java — Server.java 
public class Server {

    private static final int PORT = 12345;

    public void listen() {
        try (ServerSocket serverSocket = new ServerSocket(PORT)) {
            // Serwer nasłuchuje w nieskończoność
            while (true) {
                // accept() BLOKUJE się tu — czeka aż ktoś się połączy
                Socket clientSocket = serverSocket.accept();
                System.out.println("Nowy klient się połączył!");

                // Tutaj obsłużymy klienta (sekcja 2)
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }

    public static void main(String[] args) {
        new Server().listen();
    }
}
⚠️
Numer portu może być dowolny (np. 12345), ale musi być ten sam po stronie serwera i klienta. Porty poniżej 1024 są zarezerwowane przez system.

ClientHandler — obsługa jednego klienta 📬
Jak czytać i wysyłać wiadomości przez sieć

Po przyjęciu klienta serwer dostaje obiekt Socket. Z tego socketu możemy wyciągnąć strumień wejściowy (co klient do nas wysyła) i strumień wyjściowy (co my do niego wysyłamy).

📖
BufferedReader — czyta tekst linia po linii (readLine())
PrintWriter — wysyła tekst (println())
Argument true w PrintWriter = autoFlush — dane są wysyłane od razu bez ręcznego flush()
Java — ClientHandler.java 
public class ClientHandler implements Runnable {

    private final Socket socket;
    private final Server server;
    private PrintWriter out;
    private String login;  // zapamiętaj kto to jest

    public ClientHandler(Socket socket, Server server) {
        this.socket = socket;
        this.server = server;
    }

    @Override
    public void run() {
        try (
            BufferedReader in = new BufferedReader(
                new InputStreamReader(socket.getInputStream()));
        ) {
            // out trzeba ustawić tutaj, wewnątrz try
            out = new PrintWriter(socket.getOutputStream(), true);

            // Wyślij powitanie
            out.println("Witaj! Podaj login:");
            login = in.readLine();

            // Główna pętla — czytaj wiadomości od klienta
            String line;
            while ((line = in.readLine()) != null) {
                // readLine() zwraca null gdy klient się rozłącza
                System.out.println(login + ": " + line);
                server.broadcast(login + ": " + line);
            }

        } catch (IOException e) {
            System.out.println(login + " rozłączony");
        } finally {
            // ZAWSZE usuń klienta z listy gdy coś pójdzie nie tak
            server.removeClient(this);
        }
    }

    // Metoda do wysyłania wiadomości temu klientowi
    public void sendMessage(String msg) {
        if (out != null) out.println(msg);
    }

    public String getLogin() { return login; }
}
🐾
Dlaczego implements Runnable? Bo każdy klient będzie obsługiwany w osobnym wątku (new Thread(handler).start()). Runnable = "ta klasa może być uruchomiona w wątku".

Wielowątkowość i synchronizacja 🧵
Obsługa wielu klientów jednocześnie

Bez wielowątkowości serwer obsługiwałby klientów po kolei — jeden musiałby czekać aż serwer skończy z poprzednim. Zamiast tego każdy klient dostaje własny wątek i wszystko działa równolegle.

Uruchom ClientHandler w wątku

W metodzie listen() serwera, po accept():

Java — fragment listen() 
while (true) {
    Socket clientSocket = serverSocket.accept();

    ClientHandler handler = new ClientHandler(clientSocket, this);
    clients.add(handler);
    new Thread(handler).start();  // ← klient dostaje swój wątek
}

Problem: synchronizacja listy klientów

Wiele wątków może jednocześnie próbować dodać/usunąć klienta z listy — to wyścig (race condition). Rozwiązanie:

Java — lista klientów 
public class Server {

    // Opcja 1: synchronizedList (prostsze)
    private final List<ClientHandler> clients =
        Collections.synchronizedList(new ArrayList<>());

    // Opcja 2: CopyOnWriteArrayList (bezpieczne przy iteracji)
    private final List<ClientHandler> clients =
        new CopyOnWriteArrayList<>();

    // Broadcast: synchronized żeby wątki nie wchodziły sobie w drogę
    public synchronized void broadcast(String message) {
        for (ClientHandler client : clients) {
            client.sendMessage(message);
        }
    }

    public void removeClient(ClientHandler handler) {
        clients.remove(handler);
    }
}
⚠️
synchronized na metodzie = w danej chwili tylko JEDEN wątek może ją wykonać. Bez tego dwa wątki mogą pisać do tej samej listy jednocześnie i spowodować crash.

Baza danych SQLite & JDBC 🗄️
Od zera do rankingu — wszystko czego potrzebujesz

SQLite to baza danych, która żyje w jednym pliku (.db). Nie trzeba instalować żadnego osobnego serwera — plik tworzy się sam przy pierwszym połączeniu. W Javie rozmawiamy z nią przez JDBC (Java Database Connectivity) — wspólny interfejs do wszystkich baz danych.

🏗️
Jak to działa w skrócie:
DriverManager → tworzy Connection (połączenie z plikiem .db)
Connection → tworzy Statement lub PreparedStatement (zapytanie)
Statement.executeQuery() → zwraca ResultSet (wyniki SELECT)
Statement.executeUpdate() → zwraca liczbę zmienionych wierszy (INSERT/UPDATE/DELETE)

Krok 0 — Dodaj bibliotekę do pom.xml

SQLite nie jest wbudowane w Javę — trzeba dodać driver JDBC jako zależność Maven:

XML — pom.xml (w sekcji <dependencies>) 
<dependency>
    <groupId>org.xerial</groupId>
    <artifactId>sqlite-jdbc</artifactId>
    <version>3.43.0.0</version>
</dependency>
🐾
Po dodaniu zależności kliknij w IntelliJ ikonę słonia (reload Maven) lub uruchom mvn install. Bez tego kompilator nie znajdzie klas JDBC dla SQLite.

Połączenie otwieramy przez DriverManager.getConnection() z URL-em w formacie jdbc:sqlite:ŚCIEŻKA_DO_PLIKU.

Java — różne sposoby połączenia

Krok 2 — Tworzenie tabeli (CREATE TABLE)

Tabele tworzymy przy starcie programu, używając IF NOT EXISTS żeby nie crashować gdy tabela już jest.

SQL — typy danych w SQLite 
-- SQLite ma tylko 5 typów (ignoruje inne nazwy i konwertuje sam)
INTEGER   -- liczby całkowite (int, long)
REAL      -- liczby zmiennoprzecinkowe (double, float)
TEXT      -- napisy (String)
BLOB      -- surowe bajty (byte[])
NULL      -- brak wartości

-- Popularne constrainty:
PRIMARY KEY              -- unikalny identyfikator wiersza
AUTOINCREMENT            -- id rośnie samo (używaj z INTEGER PRIMARY KEY)
NOT NULL                 -- pole nie może być puste
DEFAULT 0                -- wartość domyślna gdy nie podasz
UNIQUE                   -- wszystkie wartości muszą być różne
Java — tworzenie tabeli przy starcie 
public class Database {

    private final Connection conn;

    public Database() throws SQLException {
        conn = DriverManager.getConnection("jdbc:sqlite:database.db");
        createTables();
    }

    private void createTables() throws SQLException {
        // Text block (Java 15+) — czytelny sposób na długi SQL
        String sql = """
            CREATE TABLE IF NOT EXISTS users (
                login    TEXT    PRIMARY KEY,
                password TEXT    NOT NULL,
                points   INTEGER DEFAULT 0
            );
            CREATE TABLE IF NOT EXISTS history (
                id        INTEGER PRIMARY KEY AUTOINCREMENT,
                winner    TEXT    NOT NULL,
                loser     TEXT    NOT NULL,
                timestamp TEXT    NOT NULL
            );
            """;

        // executeUpdate zwraca liczbę zmienionych wierszy (tu: 0, bo DDL)
        conn.createStatement().executeUpdate(sql);
        System.out.println("Baza gotowa!");
    }
}

Krok 7 — PreparedStatement — dlaczego ZAWSZE

⚠️
SQL Injection — klasyczny atak:
Wpisujesz jako login: alice' OR '1'='1
Zapytanie staje się: SELECT * WHERE login='alice' OR '1'='1'
Warunek zawsze prawdziwy → haker loguje się bez hasła! PreparedStatement traktuje parametry jako dane, nie kod SQL — atak niemożliwy.
Java — Statement vs PreparedStatement 
// ❌ ŹLE — podatne na SQL injection + wolniejsze
String sql = "SELECT * FROM users WHERE login='" + login + "'";
conn.createStatement().executeQuery(sql);

// ✅ DOBRZE — PreparedStatement kompiluje zapytanie RAZ
//            i potem tylko podmienia parametry
PreparedStatement ps = conn.prepareStatement(
    "SELECT * FROM users WHERE login = ?");  // ? to placeholder

// Ustaw parametry (indeksy od 1, nie od 0!)
ps.setString (1, login);     // TEXT
ps.setInt    (1, number);   // INTEGER
ps.setDouble (1, value);    // REAL
ps.setLong   (1, bigNum);   // duże INTEGER
ps.setNull   (1, Types.INTEGER);  // NULL

// Wykonaj
ResultSet rs = ps.executeQuery();    // dla SELECT
int rows     = ps.executeUpdate();   // dla INSERT/UPDATE/DELETE

// PreparedStatement można REUŻYĆ — zmień parametry i wykonaj ponownie
ps.setString(1, otherLogin);
ResultSet rs2 = ps.executeQuery();   // nowe zapytanie, ten sam obiekt

🍬 Smaczek — Transakcje

Transakcja to zestaw operacji, które albo wszystkie się wykonują, albo żadna. Idealne gdy musisz zaktualizować kilka tabel naraz (np. punkty wygranego I przegranego).

Java — transakcja (commit / rollback) 
try {
    conn.setAutoCommit(false);  // wyłącz auto-zatwierdzanie

    // Wszystkie te operacje muszą się udać LUB żadna
    updatePs.setInt   (1, +1);
    updatePs.setString(2, winner);
    updatePs.executeUpdate();

    updatePs.setInt   (1, -1);
    updatePs.setString(2, loser);
    updatePs.executeUpdate();

    insertHistory.setString(1, winner);
    insertHistory.setString(2, loser);
    insertHistory.executeUpdate();

    conn.commit();  // ✅ zatwierdź wszystko naraz

} catch (SQLException e) {
    conn.rollback();  // ❌ błąd → cofnij wszystkie zmiany
    throw e;
} finally {
    conn.setAutoCommit(true);  // przywróć domyślne zachowanie
}

🍬 Smaczek — try-with-resources i zamykanie

Connection, Statement i ResultSet to zasoby, które trzeba zamknąć. try-with-resources robi to automatycznie.

Java — czyste zamykanie zasobów 
// Stary sposób — trzeba pamiętać o close() w finally
PreparedStatement ps = null;
ResultSet rs = null;
try {
    ps = conn.prepareStatement("SELECT ...");
    rs = ps.executeQuery();
    // ...
} finally {
    if (rs != null) rs.close();
    if (ps != null) ps.close();
}

// ✅ Nowy sposób — try-with-resources (zamknie samo po wyjściu z bloku)
try (PreparedStatement ps = conn.prepareStatement("SELECT ...");
     ResultSet rs = ps.executeQuery()) {

    while (rs.next()) {
        // ...
    }
} // ps i rs zamknięte automatycznie

// Connection trzymaj otwarte przez cały czas życia programu
// (zamknij tylko na koniec, np. w metodzie close())
public void close() throws SQLException {
    conn.close();
}

Pełna klasa Database — gotowa do kolokwium

Java — Database.java (kompletna) 
import java.sql.*;
import java.util.*;

public class Database {

    private final Connection conn;

    public Database() throws SQLException {
        conn = DriverManager.getConnection("jdbc:sqlite:database.db");
        conn.createStatement().executeUpdate("""
            CREATE TABLE IF NOT EXISTS users (
                login    TEXT    PRIMARY KEY,
                password TEXT    NOT NULL,
                points   INTEGER DEFAULT 0
            )
            """);
    }

    // SELECT — autentykacja
    public boolean authenticate(String login, String password) {
        try (PreparedStatement ps = conn.prepareStatement(
                "SELECT 1 FROM users WHERE login=? AND password=?")) {
            ps.setString(1, login);
            ps.setString(2, password);
            return ps.executeQuery().next();
        } catch (SQLException e) { return false; }
    }

    // INSERT — dodaj użytkownika
    public void addUser(String login, String password) {
        try (PreparedStatement ps = conn.prepareStatement(
                "INSERT OR IGNORE INTO users (login,password) VALUES (?,?)")) {
            ps.setString(1, login);
            ps.setString(2, password);
            ps.executeUpdate();
        } catch (SQLException e) { e.printStackTrace(); }
    }

    // UPDATE — zaktualizuj punkty
    public void updatePoints(String login, int delta) {
        try (PreparedStatement ps = conn.prepareStatement(
                "UPDATE users SET points = points + ? WHERE login = ?")) {
            ps.setInt   (1, delta);
            ps.setString(2, login);
            ps.executeUpdate();
        } catch (SQLException e) { e.printStackTrace(); }
    }

    // SELECT z ORDER BY — ranking
    public Map<String,Integer> getLeaderboard() {
        Map<String,Integer> result = new LinkedHashMap<>();
        try (ResultSet rs = conn.createStatement().executeQuery(
                "SELECT login, points FROM users ORDER BY points DESC")) {
            while (rs.next())
                result.put(rs.getString("login"), rs.getInt("points"));
        } catch (SQLException e) { e.printStackTrace(); }
        return result;
    }

    // DELETE — usuń rekordy bana
    public int deleteUserRecords(String login) {
        try (PreparedStatement ps = conn.prepareStatement(
                "DELETE FROM history WHERE winner=? OR loser=?")) {
            ps.setString(1, login);
            ps.setString(2, login);
            return ps.executeUpdate();  // ile wierszy usunięto
        } catch (SQLException e) { return 0; }
    }
}
🐾
Szybka ściąga: potrzebujesz danych → executeQuery() → iteruj rs.next()
Modyfikujesz bazę → executeUpdate() → zwraca liczbę zmienionych wierszy
Tworzysz/kasujesz tabele → executeUpdate() lub execute()

UWAGA na wątki! Canvas można rysować TYLKO z wątku JavaFX. Serwer działa w innym wątku, więc musisz owinąć każde rysowanie w Platform.runLater().

Platform.runLater() — złota zasada

Java — rysowanie z wątku sieciowego 
// W ClientHandler, gdy dostaniesz dane odcinka:
double x1 = ..., y1 = ..., x2 = ..., y2 = ...;
Color color = ...;

// NIE możesz tu rysować bezpośrednio!
// ❌ gc.strokeLine(x1, y1, x2, y2);  ← BŁĄD (zły wątek)

});

                case DOWN  -> offsetY += 10;

                case RIGHT -> offsetX += 10;
            }
            redrawAll();  // przerysuj wszystkie zapamiętane odcinki
        });
    }
}

Enum z metodami ✂️🪨📄
Papier-kamień-nożyce z K2 2024 — wzorzec do zapamiętania

W Javie enum to nie tylko lista stałych — może mieć metody, jak zwykła klasa. To bardzo elegancki sposób na enkapsulację logiki gry.

Java — Gesture.java 
public enum Gesture {
    ROCK, PAPER, SCISSORS;

    // Konwertuj tekst od klienta na gest
    public static Gesture fromString(String s) {
        return switch (s.toLowerCase().trim()) {
            case "r" -> ROCK;
            case "p" -> PAPER;
            case "s" -> SCISSORS;
            default -> throw new IllegalArgumentException("Nieznany gest: " + s);
        };
    }

    // Porównaj z innym gestem
    // Zwraca:  1 jeśli THIS wygrywa
    //          0 jeśli remis
    //         -1 jeśli THIS przegrywa
    public int compareWith(Gesture other) {
        if (this == other) return 0;  // remis
        return switch (this) {
            case ROCK     -> other == SCISSORS ? 1 : -1;
            case PAPER    -> other == ROCK     ? 1 : -1;
            case SCISSORS -> other == PAPER    ? 1 : -1;
        };
    }
}
✅
Użycie: Gesture g = Gesture.fromString("r"); → ROCK
ROCK.compareWith(SCISSORS) → 1 (ROCK wygrywa)
ROCK.compareWith(PAPER) → -1 (ROCK przegrywa)

Interfejsy funkcyjne — wzorzec callback 🔔
Jak powiadomić serwer gdy gra się skończy

Interfejs funkcyjny to interfejs z jedną metodą. Można go przekazać jako argument, przechowywać w polu i wywołać w odpowiednim momencie. To jak zostawienie karteczki "zadzwoń do mnie gdy X".

Java — wzorzec onEnd w klasie Duel 
public class Duel {

    private Player player1, player2;
    private Gesture gesture1, gesture2;

    // Pole callback — "co zrobić gdy gra się skończy"
    // Runnable = interfejs funkcyjny z metodą run()
    private Runnable onEnd;

    public void setOnEnd(Runnable onEnd) {
        this.onEnd = onEnd;
    }

    public synchronized void handleGesture(Player player, Gesture gesture) {
        if (player == player1) gesture1 = gesture;
        else                   gesture2 = gesture;

        // Gdy OBAJ gracze oddali gest — wywołaj callback
        if (gesture1 != null && gesture2 != null) {
            if (onEnd != null) onEnd.run();
        }
    }

    // Wynik gry: null = remis, inaczej zwycięzca i przegrany
    public Result evaluate() {
        int cmp = gesture1.compareWith(gesture2);
        if (cmp == 0) return null;  // remis
        return cmp > 0
            ? new Result(player1, player2)
            : new Result(player2, player1);
    }

    // Zagnieżdżony rekord — wynik pojedynku
    public record Result(Player winner, Player loser) {}
}

private void startDuel(ClientHandler p1, ClientHandler p2) {
    Duel duel = new Duel(p1, p2);

Java Swing — GUI bez JavaFX 🪟
Okna, przyciski, pola tekstowe — klasyczny interfejs graficzny

Swing to klasyczna biblioteka GUI wbudowana w Javę (pakiet javax.swing). Nie wymaga żadnych dodatkowych zależności — wystarczy import. Swing działa na wszystkich systemach, choć wygląda bardziej "oldschoolowo" niż JavaFX.

💡
Swing vs JavaFX: Swing jest starszy i prostszy do szybkiego prototypowania. JavaFX ma FXML i bardziej nowoczesny wygląd. Na kolokwium — jeśli zadanie nie precyzuje, Swing jest OK i łatwiej go napisać z pamięci.

JFrame to główne okno aplikacji. Niemal zawsze rozszerzasz tę klasę lub tworzysz jej instancję w konstruktorze.

import javax.swing.*;

public class MinimalneOkno extends JFrame {

Swing + wątki — aktualizacja GUI z innego wątku

Tak jak JavaFX ma Platform.runLater(), Swing ma SwingUtilities.invokeLater(). Gdy odbiorca TCP (inny wątek) chce zmienić coś w GUI, musisz to opakować:

Java — aktualizacja GUI z wątku sieciowego 
// W wątku odbierającym wiadomości z serwera:
while ((line = in.readLine()) != null) {
    final String msg = line;
    SwingUtilities.invokeLater(() -> {
        // To jest bezpieczne — wykonuje się na EDT
        chatArea.append(msg + "\n");
        chatArea.setCaretPosition(chatArea.getDocument().getLength()); // scroll na dół
    });
}
✅
Dobra praktyka: zmienna msg musi być final (lub efektywnie final) żeby można ją używać w lambdzie. Zawsze tak rób gdy przekazujesz zmienną pętli do invokeLater.

Kompletny czat Swing — klient z GUI

Java — ChatClient.java (GUI Swing + socket) 
import javax.swing.*;
import java.awt.*;
import java.io.*;
import java.net.*;

public class ChatClient extends JFrame {

    private JTextArea chatArea;
    private JTextField inputField;
    private PrintWriter out;

    public ChatClient() {
        setTitle("Czat");
        setSize(500, 400);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);

        // Pole z historią wiadomości (tylko do odczytu)
        chatArea = new JTextArea();
        chatArea.setEditable(false);
        chatArea.setLineWrap(true);
        JScrollPane scroll = new JScrollPane(chatArea);  // dodaj pasek przewijania

        // Pole do wpisywania + przycisk wysyłania
        inputField = new JTextField();
        JButton sendBtn = new JButton("Wyślij");

        // Panel dolny z polem i przyciskiem
        JPanel bottomPanel = new JPanel(new BorderLayout());
        bottomPanel.add(inputField, BorderLayout.CENTER);
        bottomPanel.add(sendBtn, BorderLayout.EAST);

        add(scroll, BorderLayout.CENTER);
        add(bottomPanel, BorderLayout.SOUTH);

        // Wyślij po kliknięciu lub Enter
        sendBtn.addActionListener(e -> sendMessage());
        inputField.addActionListener(e -> sendMessage());

        setVisible(true);
        connectToServer();
    }

    private void connectToServer() {
        new Thread(() -> {
            try (Socket socket = new Socket("localhost", 12345)) {
                out = new PrintWriter(socket.getOutputStream(), true);
                BufferedReader in = new BufferedReader(
                    new InputStreamReader(socket.getInputStream()));

                String line;
                while ((line = in.readLine()) != null) {
                    final String msg = line;
                    SwingUtilities.invokeLater(() ->
                        chatArea.append(msg + "\n"));  // bezpieczna aktualizacja GUI
                }
            } catch (IOException e) {
                SwingUtilities.invokeLater(() ->
                    chatArea.append("[Rozłączono z serwerem]\n"));
            }
        }).start();
    }

    private void sendMessage() {
        String text = inputField.getText().trim();
        if (!text.isEmpty() && out != null) {
            out.println(text);
            inputField.setText("");   // wyczyść pole po wysłaniu
        }
    }

    public static void main(String[] args) {
        SwingUtilities.invokeLater(ChatClient::new);
    }
}
